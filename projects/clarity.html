A familiar AI failure

Applications can generate fluent answers without showing which claims are unsupported. A single confidence number is not much help if the route from an answer to that number is invisible.

Clarity approaches this as a middleware problem: intercept a request/response, run several checks and return a structured report alongside the original output.

How the proposed checks are organized

The repository describes four parallel checks: hallucination detection, reasoning validation, confidence calibration and context analysis. A LangGraph orchestrator gathers these signals and aggregates them into warnings, risk tiers and a score.

An API endpoint and developer SDK expose the verification output, while the planned dashboard is meant to make the reasoning inspectable to a developer.

What remains unproven

The repository defines the architecture and interfaces, but the public summary does not establish that a 0–100 score is calibrated against a large external truth dataset. A score is a feature; demonstrated reliability is a separate research question.

The next evaluation should measure false assurances and false alarms across tasks and models before using the score for high-stakes decisions.

What this evidence supports

Hackathon prototype. Verification architecture and scoring design are documented; independent calibration and safety certification are not claimed.
